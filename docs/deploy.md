# Deploying to Render

Swarm deploys as three Render resources from [`render.yaml`](../render.yaml):

| Resource | What runs there |
|---|---|
| `swarm-db` | Postgres 16 |
| `swarm-api` | FastAPI, the agents, the money engine, the Telegram bot (webhook) and the scheduler, in one process. Migrations run on every start. The demo world is seeded on first start. |
| `swarm-web` | The Next.js web app |

Everything runs on Render's free plans in the Singapore region. Three things about the free
plans are worth knowing before judging starts (from https://render.com/docs/free):

- **Services sleep.** A free web service stops after 15 minutes without visitors and takes
  about a minute to wake. Visitors see Render's loading page, then Swarm's own "Waking the
  demo server" screen while the API wakes; both carry on by themselves. Open the site a
  minute before you present.
- **The free database expires 30 days after you create it** (then 14 days' grace). If judging
  could run past that, create the Blueprint close to the deadline, or recreate the database
  later: delete `swarm-db`, sync the Blueprint again, and the API migrates and reseeds itself
  on its next start. Nothing but demo data lives there, as long as the shops' saved PayPal is
  also in the `PAYPAL_SHOP_<CODE>_VAULT_ID` settings (step 4).
- **750 free hours a month, shared by both services.** Left alone they only use hours while
  someone is visiting. A keep-awake pinger on both would use about 1,440 hours and get them
  suspended until next month, so don't add one, or only run it on the judging days.

## 1. Create the Blueprint

1. Push the repository to GitHub.
2. In Render: **New > Blueprint**, pick the repository. Render reads `render.yaml`.
3. Render asks for every value marked `sync: false`. For now:
   - PayPal values: copy them from your `.env` (see [paypal-setup.md](paypal-setup.md)).
     Leave them empty to run everything on the simulator.
   - `ANTHROPIC_API_KEY`: optional. Without it the agents use their deterministic policies.
   - `TELEGRAM_BOT_TOKEN`: optional. Use a separate bot from your local one, because a bot
     can have only one webhook.
   - `DEMO_PANEL_KEY`: optional, and worth setting. It stops strangers pressing Reset
     during judging. Watching needs no key: once the week has been run (step 2), **Watch a
     week run** replays the recording for every visitor. The key is only asked for when
     someone tries to run, step or reset the week, or play an owner on the phone. To let
     someone do those without typing it, give them a link that carries the key after a
     `#`, for example `https://swarm-web-xxxx.onrender.com/demo#key=YOUR-KEY`. The part
     after `#` never leaves the browser, and the site removes it from the address bar.
   - `PUBLIC_BACKEND_URL`, `PUBLIC_FRONTEND_URL`, `CORS_ORIGINS`, `NEXT_PUBLIC_API_URL`:
     put anything for now (for example `https://example.com`); you set them in step 2.
4. **Apply**. The first deploy takes a few minutes.

`SECRET_KEY` and `TELEGRAM_WEBHOOK_SECRET` are generated by Render.

## 2. Connect the two services

Once both services have URLs (shown at the top of each service page):

| Service | Variable | Value |
|---|---|---|
| `swarm-api` | `PUBLIC_BACKEND_URL` | `https://swarm-api-xxxx.onrender.com` |
| `swarm-api` | `PUBLIC_FRONTEND_URL` | `https://swarm-web-xxxx.onrender.com` |
| `swarm-api` | `CORS_ORIGINS` | `https://swarm-web-xxxx.onrender.com` |
| `swarm-web` | `NEXT_PUBLIC_API_URL` | `https://swarm-api-xxxx.onrender.com` |

Save, then **Manual Deploy > Deploy latest commit** on `swarm-web`. `NEXT_PUBLIC_API_URL` is
built into the web app, so changing it needs a rebuild. `swarm-api` restarts by itself.

Check:

- `https://swarm-api-xxxx.onrender.com/health` returns `{"status": "ok", ..., "database": "ok"}`.
- The web app's header shows the Swarm Clock and a green **Live** dot.
- `/demo` → **Run the rest of the week**, then watch `/live`.

**Run the week once before you share the link.** The run is recorded, and from then on the
home page's **Watch a week run** replays it for each visitor on their own: nothing is reset,
PayPal isn't called again, and ten judges can watch at the same time. Until a week has been
run, that button offers to run it (and asks for the demo key if you set one).

## 3. PayPal webhooks

In the sandbox **Swarm Platform** app → **Webhooks → Add Webhook**:

- URL: `https://swarm-api-xxxx.onrender.com/webhooks/paypal`
- Events: the list in [paypal-setup.md](paypal-setup.md#5-webhooks-optional-for-phase-1-needed-from-phase-2)

Copy the webhook ID into `PAYPAL_WEBHOOK_ID` on `swarm-api`. Deliveries are verified with
PayPal before Swarm uses them; unverified ones get a 400.

## 4. REAL shops on the hosted app

The REAL shops (`REAL_SHOP_CODES`) need a saved PayPal wallet:

- If you already ran `make smoke` and `make seed` locally, copy the
  `PAYPAL_SHOP_<CODE>_VAULT_ID` values from your `.env`.
- Otherwise open `https://swarm-web-xxxx.onrender.com/connect/<shop code>`, log in as that
  shop's sandbox buyer and approve the S$1.00 check (released straight away).

A saved PayPal (and a linked Telegram chat) survives the demo panel's **Reset**, so nobody
has to connect again between runs. Setting the `PAYPAL_SHOP_<CODE>_VAULT_ID` values as well
means they also survive a wiped database.

The hosted demo runs with `DEMO_MODE=true`, so the connect page works without a signed link.
If you ever run it with `DEMO_MODE=false`, give owners links from
`python -m app.cli invite <shop>` (Render shell) or the bot's `/connect` command.

## 5. Telegram

With `TELEGRAM_BOT_TOKEN` set and `PUBLIC_BACKEND_URL` on `https://`, the API registers the
webhook `/telegram/webhook` on start, protected by the generated secret. Send the bot
`/start cafe-mei` (demo mode) and the owner messages arrive there as well as in the web phone.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Header says **Connecting** forever | `NEXT_PUBLIC_API_URL` is wrong, or the web app wasn't rebuilt after changing it. |
| Browser console shows CORS errors | `CORS_ORIGINS` on `swarm-api` must be the web app's exact origin (no trailing slash). |
| `/health` shows `"database": "unavailable"` | The API started before the database was ready; redeploy `swarm-api`. |
| API logs say `Configuration: ...` | Each line names a setting that still needs a value. |
| Telegram silent | Only one webhook per bot: stop the local backend or use a second bot. |
